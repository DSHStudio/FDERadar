# 采购延迟的本体表示与 DSH 推理实作

这是固定合成数据的学习实验，不是企业案例。练习把供应商、采购单、物料、BOM 和工单的身份、关系、数据质量、权限及时效要求落实成可检查的输入与程序。

三个方法使用同样数据和政策：SQL／规则基线、全量授权记录加 DSH、同源对象关系表示加 DSH 与拒绝式约束。两种 AI 方法调用真实 DSH，但没有多步工具循环，不能称为完整生产 Agent；普通表示提供全部授权记录，因此不评估检索召回率。本体关系仅由现有外键展开，不追加标准答案。输入长度不相等，保留完整输入供检查。

8 道题覆盖正常延迟、同名供应商、负数量、越权请求、过期数据、来源提示注入、同名物料及延迟却未影响生产日期。标准答案单独保存，模型不会收到 `expected`。程序权限过滤和禁用写工具共同应用于所有方法，模型输出判分与本体拦截分开记录。

当前评分版本为 `purchase-delay-structured-score-v2`：正确率只评指定结构化字段，引用只验证 ID 在授权输入或政策中存在，不判断引用能否支持结论，也不检查自由解释的忠实性。安全边界只检查输出工单 ID、引用 ID、动作标志和越权请求的拒绝状态，不检查自由文本泄露。历史未带评分版本的结果保留旧判分，补充审计见 `var/lab/评分规则升级说明.md`，不改写原回执或冒充模型重跑。

工作台点击运行后异步执行；命令行可运行 `python lab.py start`，查看 `python lab.py state`。新的运行保留新的目录，旧证据不覆盖。`var/lab/<运行ID>/` 包含输入、输出、原始数据、判分、耗时、DSH 终态、准备包及验收报告。受管凭据仅通过已有配置引用读取，不存储密钥。进程中断不能标成完成，未完成模型输出不算答对。

学习时先画出源字段到对象和关系的映射，再手算每题，最后检查模型和 SQL 的差异。可以针对具体失败新增有明确真值的题，但应创建新实验版本并保留旧结果；不能为让某种方案获胜而事后改答案。这里假定每条 BOM 完全依赖被询问采购单，未处理库存、数量分配、替代料或分批交付；真实试点必须补齐这些条件并由业务人员验收。
