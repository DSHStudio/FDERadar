# DSH本体与FDE研究Agent

本机个人研究版。DSH官方Python SDK启动独立的sdk-minimal实例；专用profile、提示词和插件驱动三条主线。业务程序维护SQLite、原文版本、引用验证、运行状态和研究结果，不实现另一套LLM推理循环。

2026-09-28已执行多批真实公开资料采集，包括企业技术与项目页、中国企业原始报告PDF、大学教程、学术论文全文、官方订阅、出版社样章、纪录片转写和既有自动字幕导入。最新实际数量、原始标题与失败清单以[采集验收报告](./var/采集验收报告.md)和[资料目录](./var/资料目录.json)为准，不能将登记数当获取成功数。历史底稿48条保留，不改写其证据等级。DSH版本为0.1.5rc1，模型实际阅读已采集原文后提交可追溯的待复核分析。

## 从 GitHub 首次启动

仓库包含源码、DSH 插件、测试、公开信源配置和研究设计；本机数据库、采集原文、运行回执和凭据不随仓库发布。下文 `var/` 中的报告和历史验收数字属于开发机记录，不表示新克隆已经获取这些资料。

安装 Python 3.12+（当前验证版本为 3.13）后，在 PowerShell 中运行：

```powershell
git clone https://github.com/DSHStudio/FDERadar.git
cd FDERadar
py -3 -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements.txt
Copy-Item config.example.json config.json
./Run-Radar.ps1 -Action init
./Run-Radar.ps1 -Action serve
```

打开 http://127.0.0.1:8765 。配置模板使用 `examples/empty-corpus` 空底稿，可直接初始化；已有底稿可以通过 `config.json` 的 `corpusPath` 指定。案例和学习设计引用的本机资料版本不包含在仓库内，新库会如实显示缺失引用。通过 `./Run-Radar.ps1 -Action collect` 开始真实采集；新取得的版本需要重新核对引用，不会冒充历史证据。

AI 研究、翻译和通俗解读需要在运行环境安全配置 `DEEPSEEK_API_KEY`，或在本地 `config.json` 中指定已有 DSH 受管凭据文件。不要把密钥写入配置模板或提交到 Git。本地界面和公开资料采集不要求先发起模型调用。

DSH 插件打包：`./Run-DshPlugin.ps1 -Action pack`，生成本地 `dist/`。测试：`./Run-Radar.ps1 -Action test`；安装 Node.js 22+ 后可运行 `node --test dsh-plugin/test_plugin.mjs web/test_reader.js web/test_research.js`。仓库不自动创建每日任务；本机已有日程保持不变。

## 使用

在本目录PowerShell运行：

```powershell
./Run-Radar.ps1 -Action init
./Run-Radar.ps1 -Action doctor
./Run-Radar.ps1 -Action serve
```

也可运行 `./Start-Radar.ps1` 在后台启动本地服务；代码更新后用 `./Start-Radar.ps1 -Restart` 重启本服务。启动器只管理本项目记录的服务进程。

访问 http://127.0.0.1:8765 。界面可全文检索、阅读原始提取文本、筛选来源与研究主线、添加/暂停来源、启动采集和DSH研究、取消采集、审核笔记。界面每5秒（运行中）或30秒（空闲）同步数据库；这不是信源采集频率。

采集及研究命令：

```powershell
./Run-Radar.ps1 -Action collect
./Run-Radar.ps1 -Action cycle
./Run-Radar.ps1 -Action run -Task '研究本体与AI当前结合方式，获取原文并保存理论笔记，说明尚未验证的部分。'
./Run-Radar.ps1 -Action report
```

首次初始化导入相邻的本体与FDE_数据底稿，不改写原JSON。启动器优先本项目.venv；当前开发环境可复用相邻DOA已安装的匹配SDK解释器，但不导入DOA业务代码、不修改其配置。定时周期若由相邻解释器启动且缺少DSH SDK，会在任何采集开始前交由本项目已安装的.venv运行；缺少两套SDK时保留分析失败回执。独立安装使用Python 3.12或更新版本、requirements.txt，并通过-Python指定解释器；本机验证解释器为3.13.15。

config.json只存受管凭据文件位置和环境变量名。优先读取DEEPSEEK_API_KEY，否则读取已有DSH受管引用；不复制或展示密钥。使用现有DeepSeek模型服务，联网及模型调用需有可用权限与额度。

## 结构

```text
用户任务 / 现有每日触发器 cycle.py
  → pipeline.py（SQLite队列、条件请求、失败退避、版本去重）
  → acquisition.py（公开HTML/PDF/RSS/Atom/JSON/字幕，无AI改写）
  → 已保存原文 / 提取范围 / 哈希 / 时间 / 实际访问日志
  → agent.py（运行记录、独立DSH home、工具服务）
  → DSH SDK / DSH运行时 / 原生DeepSeek模型
  → 专用五项研究工具
      → DSH原生web搜索及统一安全采集器
      → 资料查询、原文版本和引用匹配
      → 暂存笔记
  → 仅在正常终态后保存pending_review笔记
  → SQLite + 本地交互工作台 + 可离线打开的报告与文本
```

前端使用原生HTML/CSS/JavaScript，无npm构建或CDN依赖；后端仅监听127.0.0.1，API校验Host/Origin和本机会话token。采集内容通过textContent展示，不能执行来源或模型提供的HTML/脚本。理论/案例/场景之外，主页优先展示真实资料库和采集缺口。

交互入口为本地服务；var/index.html仍是离线研究报告，完整资料目录见var/采集验收报告.md。保存的是提取文本及其哈希，不是完整HTTP响应或PDF二进制快照；相同URL内容改变保留旧版本。同稿多URL和不同版本不算多个独立项目。

项目案例采用原始信息展示：原始标题和逐字短摘录直接关联保存的来源版本，提供原站与已有网页提取文本入口；保留原语言，不自动重写或翻译。案例档案分为“项目事实 / 原始资料 / 研究解读”，默认事实页展示字段状态及来源短摘录，中文整理与推断单独显示。只有关键词的引用明确提示需查看上下文，不用前端长度判断改变证据等级。新case提交的title必须与文档标题一致，summary必须等于精确quote，否则拒绝入库。正文缺失、截断、版本不匹配均明确显示，不以AI概要补位。来源提取文本包含导航，原始版式和图表需查看原站。

界面采用列表与阅读详情布局：桌面并排，窄窗口从列表进入详情并可返回；理论页以课程目录切换当前单元。八个栏目在窄窗口通过栏目选择器切换。阅读器正文独立滚动，来源版本细节按需展开，引用定位必须同时匹配文档ID、哈希和逐字引文；重复原句可逐处切换，不能以相似文本替代。切页保留筛选和未提交草稿（当前页面会话内），学习记录点击保存后才持久化。场景优先展示痛点、数据前提、通过及停止条件，实作优先展示已有结果。UI验收见 `var/UI重构验收.md`。

覆盖分两套可追溯口径：var/信源覆盖统计.json保留DSH直接搜索/获取统计；var/资料目录.json记录全部后台采集及人工导入，并把正文候选、摘要、目录、部分文本、空壳分开。radar_library(kind=coverage)返回两套统计，不能相加冒充独立证据数。radar_search.scope仅记录范围，不是引擎过滤器。2026全年市场回填尚未完成、检索饱和度未测量，不能声称全网穷尽。旧版[信源覆盖审计](./信源覆盖审计.md)作为开发前快照保留，当前数字查看生成报告。

工具：radar_library、radar_read、radar_search、radar_fetch、radar_submit。所有模型请求核对工具清单；没有Shell、安装、批准或生产写入工具。引用必须属于实际抓取或显式导入的文档，并匹配全文摘要与精确短摘录。导入的历史研究JSON不能冒充新取得的第一方全文。

来源声明与研究分析分开保存，所有模型笔记保持待复核。案例FDE、本体、上线和收益分别核验；本体学术概念不归为Palantir发明；场景建议不能混入已落地项目数。引用存在不等于语义正确，仍需原始证据和实测。

## DSH 插件

FDE 雷达现提供可安装的 `dsh-plugin-fde-radar` bundle，入口为 `dsh-plugin/index.mjs`，包定义遵循 DSH 的 `dsh.bundle` 与 Cordis 插件接口。八个带 `fde_radar_` 前缀的工具连接已有本地服务，覆盖实际资料/信源/开源检索、原文分页、采集更新、DSH证据研究、中文阅读、任务查询和工作台入口。完整说明见 [插件README](./dsh-plugin/README.md)。

```powershell
./Run-DshPlugin.ps1 -Action install
./Run-DshPlugin.ps1 -Action verify
./Run-DshPlugin.ps1 -Action run -Task '查找本体与Agent结合的原始资料，保留原标题，列出处和获取范围。'
```

可分发包为 `dist/dsh-plugin-fde-radar-0.1.1.tgz`；其中不包含数据库、历史原文和密钥。安装在本工程的专用 DSH home，保持现有雷达库与每日/每周调度。Python后端仍需可运行，插件不是独立云服务。原始资料不改写，宿主插件不自动收录或升级任何项目核验等级。

真实 DSH 验收回执为 `var/dsh-plugin-verification.json`：SDK挂载和完整CLI安装的bundle分别实际查询现有资料、读取版本一致的原文、访问GitHub及阅读状态；模型响应由本机测试服务提供，未发起付费模型生成。写入工具的参数、认证重试、重复提交保护及后端接口通过独立测试。

用户授权后的 DeepSeek 在线状态查询也已完成，实际只调用一次 `fde_radar_status`，没有启动采集或研究。安装包一致性、40项测试、两种DSH集成、在线回执及能力边界见 [DSH插件验收](./var/DSH插件验收.md)。

0.1.1 复核修复了缓存查询恢复生成、长译文响应超限及历史任务遗漏问题；55项Python测试、14项Node测试和两种真实DSH集成通过，详见 [最新插件复核报告](./var/DSH插件复核报告.md)。升级插件时后端也需更新；本机服务已加载新接口。

## 中文阅读与通俗解读

每份已取得正文的资料提供“英文转中文”和“通俗解读”。阅读窗口可切换原文、中文译文及通俗解读，保持来源原标题、链接与版本不变。中文译文要求保留专名、数值、单位、条件及不确定表述；通俗解读面向普通读者解释术语与业务含义，类比与推断明确标示，不能凭空补充项目或收益。

生成由DSH执行，和采集原文及事实笔记分开保存。长文分段处理，界面显示进度与已完成部分；全部分段成功前不会标为完成。失败或取消后可重试，同一原文版本的已有结果可直接读取，原文更新后使用新版本的独立结果。只有目录、摘要或导航的页面不能冒充已获取正文来加工。

## GitHub 开源资源

工作台“开源资源”页（`/#opensource`）独立展示本体建设、数据清洗与治理、FDE 交付相关资源。首批精选 35 个仓库，包括中国开源项目；登记依据保存在 `config/github-resources.json`。每次实际采集取得 GitHub 公开元数据和原始 README，显示原始描述、许可证识别、Star、语言、最近推送、归档及分叉信息。README 进入原文库，可直接阅读、翻译和通俗解读。精选资源与检索候选分别标示，工具、框架、示例、资料清单不混作已核验的企业项目。

既有每日09:00（America/New_York）任务中的 `cycle.py --scheduled` 检查独立周周期：成功资源和新仓库发现于下一周一到期，正常由周一09:00触发更新；失败条目退避后随每日任务重试。周一UTC零点只是采集资格到期，不是独立的运行预约。错过触发需等设备和应用可运行后的实际任务。工作台可手动刷新，不新增第二个调度器。

每轮最多45次 GitHub API请求、3条轮换查询（各方向一条）、每条第1页10个结果、每条最多2个新候选、总时限480秒。配额限制按响应头退避；README 使用条件请求和哈希留存版本。候选上限120个，不声称检索穷尽；仍需复核相关性及扩展查询范围。记录保存在 SQLite 的 `github_resources`、`github_runs`、`github_snapshots` 与 `var/github/`，最近回执为 `var/github/latest-receipt.json`。

手动运行：`python github_resources.py --force`；只查看已存状态：`python github_resources.py --state`。不带 `--force` 仅检查到期项，回执标为 `due_check`，不据此认定真实自动触发。GitHub公开可见不保证许可已确认；SPDX缺失或NOASSERTION保持“许可待确认”。本模块取得的是元数据和README，不克隆、安装、执行或审计源码，不把维护者效果声明当独立验证。

## 深化研究与实作

工作台保留七个原模块，并新增“实作与试点”。理论页提供八节循序学习单元，每节有原文版本、练习、交付物和自查条件；练习记录通过本地 SQLite 持久保存，变更另留事件历史。“自行标记完成”不是客观掌握或项目验收。学习内容是研究设计，来源原句、整篇原文和 DSH 解释分开。

案例页首批五份档案：Airbus Skywise、McCarthy Pulse、中国地方病知识图谱采购、Cognite–MaMaTa、科大讯飞–国家能源招采。每份分开核对 13 类字段，包括交付方式、FDE、本体/图谱、Agent、运行、效果、金额及验收。未知保留未知；McCarthy 的嵌入式工程师描述不直接认定完整 FDE 模式。金额区分中标、合同量级和业务规模；原始标题不改写，中文研究整理位于单独的“研究解读”页签。引用检查覆盖实际文本 SHA、精确短引文及是否已有新版本，不将引用匹配提升为独立核验。

场景页补齐采购延迟、制造批次追溯、招采文档核对三个条件化研究方案。开源页为五个精选工具补入实际保存的技术文档/示例及适配边界；没有自动安装或执行上游代码。情报页可打开同源旧新文本，信源页显示逐项研究缺口及实际补采状态。不能把导航或提取变化称为新技术。

`research.py` 从 `config/research-cases.json`、`config/research-learning.json` 生成版本校验视图；GET 不采集、不改写原文。`cycle.py` 每次沿用现有每日任务导出研究审计快照，受限资料留在同一采集管线重试。`radar_library(kind=research)` 向 DSH 提供研究索引，读取单项使用 `query=精确id`；它不是原始证据，DSH 仍须回到原文阅读并提交待复核笔记。资料更新不会悄悄覆盖已绑定的历史引用。

`lab.py` 提供合成采购延迟实作：固定八题、同一授权事实和政策，比较 SQL/规则、全量授权记录+DSH、本体对象关系表示+DSH。两种 AI 方案均实际调用现有受管 DSH；首轮16次模型请求正常结束，三个方案均8/8，未观察到本体准确率增益。普通文本臂没有 top-k 截断，因此不是向量检索召回评测；本体臂输入更长，非等 token 实验。本实验没有多步工具循环或真实业务写入，不能冒称完整生产 Agent。

每次实作保留独立运行目录、合成数据、标准答案、逐题输入/输出、哈希、耗时、模型终态和试点准备包，可在页面直接阅读。自动判分只检查固定结构化字段及引用ID存在性，不验证自由文本解释的忠实性或引文支持关系；确定程序拦截与模型正确率分开统计。评分v2补充了输出工单与引用ID的授权检查，旧回执保持原样，离线复核记录见 `var/lab/评分规则升级说明.md`。没有可靠 token/计费回执，不估算调用费用或企业ROI。

实作手动命令：`python lab.py start`；只读状态：`python lab.py state`。实际网络与模型调用依赖本地服务运行环境的正常网络授权；日常采集不自动发起实作实验。结果以 `var/模块深化验收.md`、`var/research/latest.json` 和每次 `var/lab/<runId>/receipt.json` 为准。

## 获取边界

采集器自动处理公开HTML、PDF分页文本、RSS/Atom、JSON与公开VTT/SRT字幕，默认8MB、400页、900000字符上限；PDF超过范围明确标部分，扫描件标需OCR。HTTP请求、PDF子进程分别限时，DNS和每次重定向校验公网地址、连接固定已验证IP，TLS校验和robots规则保持开启。403、404、robots禁止/延后、动态空壳、超限分别记状态，失败不会被写成无更新。没有登录绕过、交互页面渲染、付费书籍获取或自动音视频转写。公开节目介绍不当完整对话；字幕需说明是否自动生成和是否对音核验。

已有合法文本和字幕可以导入，必须声明来源及自动/人工类型：

```powershell
python agent.py import-text --path '字幕.txt' --url 'https://原始节目地址' --title '节目名称' --kind transcript_auto
```

此功能不会假装自动获取音视频，也不把自动字幕视为对音核验。著作仅处理合法可访问正文；书目不能生成全书笔记。
